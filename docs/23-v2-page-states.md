## 1. 本轮完成的效果

| 情况 | 页面表现 |
| --- | --- |
| 数据尚未返回 | 骨架加载与文字提示；辅助技术可读取加载状态 |
| 尚无公开内容 | 说明内容正在整理，区别于查询条件无结果 |

首页、主题、归档、公开日记、资源与关于页接入统一状态组件；后台文章列表与编辑器接入加载状态。目录失败仍允许阅读已经成功加载的文章。公开统计仍来自后端公开数据，失败不会伪装成零访问量。

## 2. 代码位置与数据流

- `frontend/src/components/PageState.vue`：实际复用的加载、错误、空与404组件；通过 `retry` 事件让页面重新调用原有加载函数。
- `frontend/src/pageMeta.js`：页面标题、description、robots。用当前路由与查询参数标识内容，卸载时只清理所属组件的元信息，避免旧页面清除新标题。
- `frontend/src/views/NotFoundView.vue` 与 `main.js`：未知路由的站内返回入口。
- `App.vue`：跳到主要内容、页面切换后的主体焦点。筛选和锚点变化保留原有滚动行为。
- `ArticleDetailView.vue`：合法正整数编号检查、404与网络错误分开处理、15秒请求上限、文章标题与摘要。
- `SiteHeader.vue`、`AdminConfirmDialog.vue`：菜单和弹窗Escape关闭、焦点返回。

文章数据链路仍为：路由编号 → 公开API → 最新请求编号检查 → 正文与页面元信息。非法编号直接显示站内404；合法但不可公开的编号由后端返回404。

页面描述通过DOM属性写入，不插入HTML；文章标题最多取100字符用于浏览器标题，描述最多180字符，正文标题仍完整展示。管理页面和404设置 `noindex, nofollow`。这是客户端基础元信息，并不等于已完成服务端渲染、搜索引擎收录或社交分享卡片。

## 3. 本轮修复的边界

1. 旧文章404晚于新文章成功返回时，必须先检查请求编号，再改变 `notFound`；否则会遮住新正文。
2. `/articles/1/no-page` 应进入独立404；文章滚动等待只匹配真正的单段详情路由，避免错误路径一直等待不存在的正文。
3. 资源加载或失败期间隐藏尚未确认的结果数，避免先显示假的“0项”。
4. 网络断开、HTTP 5xx、超时和非法JSON转换为可理解的状态说明，支持原地恢复。

```powershell

```

若前端已启动，刷新即可；若静态预览使用旧产物，先重新构建并重启预览。本轮只修改前端和文档，已运行的后端可继续使用。个人库已经执行第六轮007，**不要再次执行迁移脚本**。
