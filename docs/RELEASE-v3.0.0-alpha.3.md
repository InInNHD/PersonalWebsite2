# v3.0.0-alpha.3 — 编辑冲突检测与编辑稿隔离

日期：2026-10-25。基于v3.0.0-alpha.2（2714be2），本轮是第四轮4A阶段预发布，不代表整个第四轮或第三版正式完成。前端、锁文件和Maven构建版本统一为3.0.0-alpha.3。

## 升级前必读

**本版本需要008迁移。个人库尚未执行008；本次代码发布不会自动迁移数据库。** 不可沿用alpha.2的“无需SQL”说明。

1. 停止后端及所有写入，关闭旧管理端窗口；备份数据库、配置和匹配媒体，使用新的备份目录。
2. 确认目标库与当前结构，执行一次 `database/008-article-editing.sql`。新安装依次执行000～008。
3. 008增加 `article.write_version`（BIGINT、非空、默认0）及 `article_edit`、`article_edit_tag`、`article_edit_media` 三表，总业务表从8变为11；旧文章内容和发布状态不变，初始编辑稿为空。
4. 若已有部分008结构，停止并核对，不要盲目重跑。MySQL DDL不是整份脚本可回滚事务，失败后不要继续启动新版写入。
5. 应用账号需新表读写权限，不扩大为DDL权限；同步更新并重启前后端、重新登录。旧管理端不携带版本条件，不能混用。
6. 回退代码前必须配合相应升级前数据恢复；先在全新专用库验证恢复，不能只换回旧JAR继续写新结构。

详细备份、结构核对SQL和操作步骤见[4A升级指南](34-v3-reliable-writing-a.md)。本次没有执行个人库008，也没有发布个人草稿或修改媒体。

## 完成功能与接口变化

- 保存已公开文章只更新独立编辑稿，访客继续读取上次公开版本；明确发布时，正文、元数据、分类标签、封面及正文媒体关联在同一事务内切换。
- 所有已有文章写入携带If-Match版本，在行锁内检查。过期返回412，缺失428，非法400；自定义客户端也需适配新版写入条件。
- 两窗口冲突时保留本地输入与旧版本，不擅自重试覆盖；可查看服务器稿，重新加载必须经过放弃本地修改确认。
- 提示“编辑稿已保存，公开版本尚未更新”，列表展示待发布状态，并按编辑稿字段搜索/筛选。
- 撤回、回收和恢复保留编辑稿；恢复仍是非公开草稿，首次发布时间保持原规则。

“待发布”表示存在已保存编辑稿，不是逐字比较；相同内容保存也会推进版本。分类/标签名称的全站重命名仍影响共享引用，不属于单篇编辑稿隔离。
