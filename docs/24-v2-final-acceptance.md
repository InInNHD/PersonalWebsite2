## 二、修复恢复工具的失败处理

本轮实测发现：SQL导入失败时，原工具留下本次创建的恢复库。已在 `scripts/local-backup.py` 修复：

1. 只有CREATE DATABASE成功之后才进入回滚范围；同名已有库创建失败时绝不删除它。
2. 导入、媒体提取或校验失败时，删除本次创建的专用库和确实写入的媒体文件。
3. 媒体采用独占创建，只删除空的恢复目录，不递归删除其他内容。
4. 回滚本身失败时报告残留对象类型，保留现场供检查，不误报已清理。

标准库测试无需连接MySQL或读取个人配置：

```powershell
python -m unittest discover -s scripts/tests -v
```

5项覆盖导入失败、已有库保护、媒体提取失败、回滚失败提示及正常恢复。另有真实MySQL错误SQL导入验证，修复后未残留恢复库。完整演练使用修复后的工具执行。

## 三、继续使用当前项目

本轮没有新迁移，没有Java或依赖变化。当前个人库已完成007，**不要再执行000～007**。

旧安装升级必须先备份，再按自身缺失编号执行迁移；不得把本次专用库名替换成个人库后直接运行验收样例。新安装才从000开始。

本机日常使用仍按照README配置环境变量，启动自己的前后端。备份前必须停止应用及其他工具写入数据库和媒体。当前备份工具恢复命令只允许全新的 `pw_media_restore_` 专用库和不存在的媒体目录，不会覆盖现有业务库。

本轮演练备份保留在Git忽略目录：

- `backups/v2-final-legacy-20261022`：升级前旧版样例。
- `backups/v2-final-complete-20261022`：完整数据库/媒体样例。

它们属于演练样例，不能代替你个人内容的备份。工具会复制本机配置，备份只保留本机，不能上传GitHub。
