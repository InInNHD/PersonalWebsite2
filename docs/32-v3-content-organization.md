# 第三版第二轮：首页、文章库与内容组织

## 本轮页面

| 地址 | 用途 |
| --- | --- |
| `/` | 紧凑介绍、精选或公开记录、学习路径、最近与置顶、项目入口 |
| `/articles` | 完整文章库，原有栏目、分类、标签、标题/摘要搜索和分页；支持紧凑列表 |
| `/topics` | 学习专题入口，以及原有分类和标签目录 |
| `/collections/{slug}` | 按编排顺序阅读一个专题；正文底部使用专题上一节/下一节 |
| `/projects` | PersonalWebsite2 案例、关联实践笔记、全部公开仓库和三类更新记录 |
| `/about` | 保留作者资料和原项目记录，新增独立项目页入口 |

第二版的 `/?type=NOTE&page=2#entries`、`/#entries`、`/#article-search` 会用 `replace` 跳到文章库；筛选参数和支持的锚点保留。裸 `/` 显示新首页。文章详情地址不变，`from` 支持旧首页、文章库、专题、项目及原有内容目录，拒绝外部网站和管理地址。

## 精选与专题如何配置

本轮不增加数据库表，不需要执行 SQL。使用后端资源文件：

`personalwebsite/src/main/resources/presentation.json`

默认内容是空编排：

```json
{
  "featuredArticleIds": [],
  "collections": [],
  "projectArticleIds": []
}
```

- 没有精选时，首页显示原公开列表中的首篇，标题为“公开记录”，不冒充人工精选。
- 没有专题或某专题不足两篇公开文章时，专题入口隐藏。
- `projectArticleIds` 是 **PersonalWebsite2 案例**的实践笔记，留空时整个关联阅读区隐藏。
- 原置顶仍控制文章库和“最近与置顶”的排序；精选按这里的数组顺序显示，互不替代。
- 编辑该文件后，IDEA 重新构建并启动后端；使用 JAR 时需重新打包。浏览器刷新即可读取新的编排。
- 此文件属于公开源码，只填写愿意公开的专题名称与说明，不放私人日记提纲、凭据或正文。

### 填写示例

以下 `101`、`102`、`103` **只是示例编号**。先在管理端核实文章编号及公开状态，再替换为你的文章；不要直接复制编号或为了凑专题发布私人草稿。

```json
{
  "featuredArticleIds": [103],
  "collections": [
    {
      "slug": "building-my-website",
      "title": "从接口到个人网站",
      "description": "按接口、页面和验收的顺序，回看实现过程。",
      "articleIds": [101, 102, 103]
    }
  ],
  "projectArticleIds": [101, 103]
}
```

限制：精选最多3个编号，专题最多12个，每个专题最多30个编号；项目实践笔记最多10个编号。编号必须为正整数，重复编号在公开结果中去重；不存在、草稿、回收中的编号被过滤。专题 `slug` 不重复，最长60字符，只允许小写字母、数字与中间连字符；标题1～80字符，说明最多300字符。配置格式或边界错误会阻止启动，请根据日志修正。

### 公开状态与撤回

`GET /api/presentation` 一次批量读取候选文章及标签，只返回公开摘要，不发送原始配置编号或正文。

`GET /api/collections/{slug}` 返回过滤后的有序文章。少于两篇或不存在均返回404；不会把隐藏专题的标题与说明发给访客。正文中的专题前后篇使用同一接口，所以数量与顺序一致。撤回/回收后下一次请求立即生效；已经打开的页面需要刷新或导航后重新读取，不是实时推送。

当前只维护一个本站案例。其他公开仓库仍全部展示，并继续区分 `PUSH`、`RELEASE`、`COMMIT`，fork 标记及历史范围说明不变。

## 备份与升级

新配置位于源码资源目录，现有源码备份会纳入该文件，JAR 打包也包含它。数据库仍是000～007后的8张表，本轮没有迁移脚本，也没有新的运行数据目录。

测试使用 `app.presentation` 指向隔离配置文件。日常使用推荐维护上述资源文件；如果自行指定外部文件，现有源码备份**不会自动收集工作区外的文件**，需自行纳入备份。

升级时同时更新前端与后端：新前端会调用新增接口。后端没更新时文章库仍能访问，但精选、专题和实践笔记会显示加载失败。

## 自查路径

1. 启动两端，裸 `/` 为新首页；进入文章库，再打开旧 `/?type=NOTE&page=2#entries`，确认地址迁移及筛选保留。
2. 打开列表第二页，点击正文后返回，检查页码、条件和位置；在文章库切换紧凑列表。
3. 选至少两篇已公开文章写入专题，重启后端；检查专题顺序、正文上一节/下一节及返回专题。
4. 撤回其中一篇：刷新专题及首页；不足两篇时入口消失，专题直达显示不可用。不要用私人日记做验收样例。
5. 查看项目页：本站案例、关联笔记、全部公开仓库和三类更新筛选均可操作。

## 本轮边界

搜索仍只覆盖标题与摘要；正文检索、命中片段、字号和专注阅读在第三轮实现。后台编排入口在第四轮评估；当前通过 JSON 维护。实体手机触摸和软键盘验收仍按之前约定暂缓。
