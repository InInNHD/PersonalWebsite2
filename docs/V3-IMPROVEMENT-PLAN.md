## 5. 分轮实施与验收

### 第一轮：内容策划与可操作视觉样稿

1. 整理当前公开内容、草稿、资源、GitHub项目的清单；涉及私有内容的清单留本机，公开文档只记录状态。
2. 从现有稿件和公开项目挑选首页代表内容，标出需用户补充的真实经历、图片和结论。缺资料不虚构。
3. 产出首页、文章库、项目页、阅读页的桌面1440px及手机390px样稿，并补320/768px适配检查。
4. 用同一组示例内容比较前后效果，避免拿填满内容的参考站与本机空库直接比较。样稿数据明确标为演示。
5. 用户确认内容密度、主视觉、导航和项目说明方式后，再进入业务实现。

验收：首次访问能明确找到作者、代表文章和项目；搜索及文章入口可操作；窄屏无整页溢出，长标题/无封面/空内容有合理效果；暗色技术风格延续。只完成样稿不创建业务Release。

### 第二轮：首页、文章库与内容组织

2026-10-24 已完成。实际选择：JSON资源配置编排精选、专题和本站项目文章关联，不增加数据库表；配置纳入现有源码备份及JAR。后台编辑入口留到第四轮，私人内容保持原发布状态。

先拆分首页/文章库并迁移旧链接，再增加精选与学习专题，最后完善项目案例。项目与文章的关联用已有文章ID和仓库标识；初期采用明确字段和排序，不引入通用页面搭建器。

验收：旧链接筛选及返回仍有效；精选与专题只读取已发布且未回收文章；撤回后列表、计数、前后篇一致更新；7个仓库和三类记录的既定展示范围不被精选筛掉。增加的新表和设置从本轮起纳入备份清单。

达到独立可使用且回归通过的节点时，提醒用户可推送并创建第三版阶段预发布；是否执行仍由用户决定。

### 第三轮：正文搜索与阅读体验

先实现有边界的服务端正文检索和片段返回，客户端通过文本节点高亮；优先复用MySQL及现有分页。中文短词、英文、代码符号均纳入样例；是否使用全文索引依据实测选择，不能只因功能名叫“全文搜索”就引入Elasticsearch。

补字号与专注模式，主题内按顺序阅读，分享链接移除`from`等浏览状态参数。保留现有安全Markdown、阅读位置及媒体隔离。

验收：仅正文出现的词可命中；草稿/回收内容及其摘要不能进入结果；同分结果分页稳定；连续快速搜索不显示旧响应；恶意文本以文字呈现；字号改变后目录定位和手机代码滚动仍可用。

### 第四轮：可靠写作与站点资料管理

按顺序完成：版本标识与冲突检测 → 编辑稿与公开版分离 → 有限修订历史及恢复 → 自动保存 → 后台公开资料维护。数据设计在这一轮开始时给出具体迁移，不在规划阶段提前执行SQL。

自动保存仅保存编辑稿，不能更新正在公开的版本。已发布文章修改标题/正文/封面/标签时，都应沿用相同发布语义；图片引用也需区分编辑稿与公开版，未发布的新图不能因关联公开文章就提前可见。修订恢复先回到编辑稿，重新发布仍是明确操作。

验收：两窗口编辑同文，旧版本提交收到可理解的冲突提示并保留输入；断网/401/超时不误报已保存；恢复修订不会偷偷改公开文；发布一次后正文、搜索、媒体及订阅一致；自动保存失败可手动重试，新增稿不重复创建。刷新/崩溃后的恢复范围明确记录，不能把beforeunload提醒当作自动备份。

站点资料仅管理已定义的公开字段，长度、URL、空字段回退及刷新读取均可验收。文章导入导出列为后续可选补充，本轮先保障写作可靠性。

### 第五轮：分享、订阅与加载效率

先验证公开文章在不运行JavaScript时的HTTP输出，再选择最小可行渲染方案。可比较Spring Boot提供公开文章HTML壳与受控预渲染；只有确实需要整站SSR时才评估框架迁移。禁止只动态插入OG标签就宣称分享卡片已完成。

实现公开站点基准URL配置、canonical、OG、RSS、sitemap与正确的404；本机以测试域名/地址验收协议，正式域名与实际收录验证留到上线阶段。不要把localhost写进正式分享文件。

预渲染方案必须处理发布/撤回后的失效：旧HTML、摘要、图片元信息和feed不能泄露已撤回内容；外部已抓取副本无法保证即时消失，记录这一边界。

生产构建记录首屏请求、脚本体积、大图、加载时间和布局偏移；按测量结果做路由懒加载、图片尺寸优化等。Vue官方也建议先测量，再按页面需要拆分代码与选择渲染方式：[Vue性能指南](https://vuejs.org/guide/best-practices/performance.html)。JavaScript可被部分搜索引擎渲染，但抓取与渲染是不同步骤，不能保证所有分享客户端执行JS：[Google JavaScript SEO说明](https://developers.google.com/search/docs/crawling-indexing/javascript/javascript-seo-basics)。

验收：原始HTTP文章响应有对应标题/摘要/规范链接；草稿返回404且不进入feed/sitemap；无效ID不是200空壳；RSS XML转义正确；撤回后重新请求各输出均排除内容。用生产构建、固定设备/浏览器与网络配置跑三次，记录中位数及资源变化。

性能目标建议参考LCP≤2.5秒、CLS≤0.1、INP≤200毫秒；这些是Web Vitals良好体验阈值，不是当前测得结果。实验室测试与真实用户75百分位结果要区分，本机无法证明线上INP达标：[Web Vitals](https://web.dev/articles/vitals)。

### 第六轮：第三版候选整站验收

集中完成新装、从第二版升级、含全部新增表/设置/编辑稿/修订/媒体的备份恢复，以及全链路回归。复用现有工具，避免因为表数增加而遗漏新数据。

整理常规测试和docs/checks专项的运行入口，准备CI：真实MySQL测试只能使用隔离测试库和临时账号；不能让CI读取个人配置、数据库或媒体。

验收包括：浏览/搜索/专题/项目/资源、保存编辑稿/发布/撤回/回收/修订恢复、两窗口冲突、无JS分享输出、生产构建路由直接刷新、键盘与200%缩放、四档屏宽、新装升级与恢复。浏览器增加Firefox等可获得环境；Safari/实体手机若仍不可用如实列未验证，不静默判通过。

只有这些范围完成且页面效果获用户认可，才准备`v3.0.0-rc.1`；正式`v3.0.0`另行确认。阶段版本可采用`v3.0.0-alpha.N`，实际编号到发布时核对。本轮保持2.0.0-rc.1构建版本。

## 6. 暂不纳入核心范围

- 微服务、消息队列、独立搜索集群、通用CMS、多人协作权限：没有当前负载或用户需求支撑。
- 评论、点赞、聊天室、音乐、相册、AI自动写文：参考项目具备并不代表本站必须增加。评论可在真实公开使用后单独决策。
- 自动发布个人草稿、撤回旧测试文章、替用户补写个人经历：需要逐项内容确认。
- 云服务器购买、域名、公开部署：本机产品验收之后单独推进，不将部署当作第三版开始条件。
