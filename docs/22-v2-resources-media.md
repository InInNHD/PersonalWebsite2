# 第六轮：资源与图片管理

更新：2026-10-22。第五轮已由用户完成发布，本轮在其基础上直接实现资源目录、本地图片库与媒体备份恢复，完成统一验收。具体证据见 [验收记录](V2-RESOURCES-MEDIA-ACCEPTANCE.md)。

## 1. 资源使用流程

后台 `/admin/resources` 增加用途分组、组内排序、五种本站SVG图标与推荐理由。先在页面下方新建分组，填写名称和排序数字，再给资源选择分组。分组与资源分别保存；改名沿用原编号，关联不会丢失。排序数字越小越靠前。

公开 `/resources` 按分组展示卡片，包含域名、图标、说明、推荐理由和新标签页外链提示。点击分组后可以搜索当前组的名称、说明及推荐理由，条件保存在 `group`、`q` 网址参数中。只出现公开资源及含公开资源的分组，旧资源归入“未分组”。图标使用本站SVG，不请求第三方favicon。

## 2. 图片使用流程

在文章编辑页下方的图片库中选择本地PNG或JPEG。上传成功后可“设为封面”或“插入正文”，随后保存文章；首次保存仍取得正式文章编号。上传失败保留文件选择，可使用“重试上传”；正文与其他字段不会丢失。

- 每张最大5MiB，边长最多6000px，总像素最多2000万。
- 后端核对实际图片内容、扩展名、MIME及尺寸，再重新编码，随机命名；不保留原文件名和图片元数据。
- 上传、读取图片库及草稿预览需要管理员认证；上传校验CSRF。草稿预览使用受保护请求和临时blob地址，不把认证信息写入图片URL。
- 图片只有在至少一篇关联文章已发布且未回收时才可通过 `/api/media/文件名` 访问。撤回或回收最后一篇公开关联后，新请求返回404；读取响应不缓存。
- 编辑器使用现有Markdown解析器提取真实图片/链接目标，随保存请求明确提交 `bodyMediaUrls` 授权关联；代码块、外部URL参数中的相似文字不会使图片公开。查询参数与片段支持正常关联。
- 移除正文图片或清空封面并保存后，对应关联解除。恢复文章仍先回草稿。文件保留在图片库，当前版本不提供永久删除；备份包含未使用图片。

每篇文章最多提交200个正文媒体目标。已有HTTP/HTTPS封面继续使用；本地封面使用上传后返回的 `/api/media/...` 地址。服务器不下载外部图片。

## 3. 同源访问与存储位置

图片接口都在 `/api` 下，现有Vite代理已覆盖上传、管理员预览和公开读取，不需要额外跨域配置。生产预览或今后部署也应将 `/api` 代理到Java服务，不能把媒体磁盘目录直接映射为公开静态目录，否则会绕过草稿隔离。

`app.media.directory` 默认 `./media`，相对于Java进程工作目录。建议IDEA工作目录设为 `E:\PersonalWebsite2\personalwebsite`；也可设置明确的绝对路径，避免从不同目录启动后看不到旧图片：

```properties
app.media.directory=E:/PersonalWebsite2/personalwebsite/media
```

配置示例支持环境变量 `MEDIA_DIRECTORY`。本地实际配置可按上面直接填写；自定义媒体目录时，备份命令显式传入同一目录。媒体文件不提交到Git，现有默认媒体目录已加入忽略。

## 5. 数据库、配置与媒体备份

Windows使用Python 3.12+，准备MySQL 8客户端。脚本读取本机 `application.properties` 或当前进程的 `DB_URL/DB_USERNAME/DB_PASSWORD`；连接值不会输出，临时客户端配置执行后删除。MySQL客户端不在默认路径时传 `--mysql-bin`。

先停止后端及其他写入工具，确保选中的媒体目录就是当前应用使用的目录，再在项目根目录执行：

```powershell
python scripts/local-backup.py backup --offline --media E:/PersonalWebsite2/personalwebsite/media
```

`--offline` 表示你已确认停止所有相关写入，脚本不会替你停止IDEA服务。默认生成新的 `backups/日期时间-media`，包含数据库SQL、媒体ZIP、当前工作树源码ZIP、本地配置及SHA256清单；源码包含未提交业务文件，但不包含Git忽略的私有配置、备份和媒体。配置另单独保存。环境变量中的实际秘密仍需自行离线保管；脚本不自动记录或执行秘密环境变量。

脚本会核对数据库中的媒体文件名、文件是否存在及字节数，拒绝漏图备份；文件清单在备份前后做SHA256检查。工作区内只允许把备份放到已忽略的 `backups/`，拒绝符号链接、junction和越界路径。数据库、配置及备份均含私有内容，不上传GitHub。

## 6. 隔离恢复

只恢复自己用本工具生成且可信的备份；SHA256用于检查完整性，不验证来源。目标数据库必须不存在，名称以 `pw_media_restore_` 开头；媒体目标目录也必须不存在，不会覆盖个人库或现有目录：

```powershell
python scripts/local-backup.py restore --offline `
  --backup E:/PersonalWebsite2/backups/替换为备份目录 `
  --database pw_media_restore_manual `
  --media E:/PersonalWebsite2/artifacts/manual-restored-media
```

恢复前验证必需文件、归档路径和媒体SHA256，之后创建新库、导入SQL并还原媒体。恢复命令不自动覆盖源码或加载私有配置。启动恢复副本时，显式把数据库连接改为这个专用库，把媒体目录改为恢复目录，另用空闲端口；核对文章、资源、封面和正文图片，再决定后续人工切换。

如果导入本身失败，留下的专用库用于检查，不自动删除或覆盖，处理后使用新的目标名称重试。本轮已在独立库完成8表逐行核对、2张图片SHA256检查，以及恢复服务的封面和正文图片读取。
