## 1. 重新界定当前完成度

已有文章、分类标签、资源、搜索分页、归档、管理员写作、草稿隔离、备份恢复，以及基础暗色样式。此前自动化和浏览器验收证明这些已实现流程在测试范围内可运行。

## 4. 第二版的设计方向

延续用户选择的暗色技术风格，形成“个人学习与生活记录”的站点。采用深色背景、较轻的分隔线、一种主要强调色，配合有内容含义的图像和清晰文字层级。

以下为设计起点，最终以样稿调整为准：

- 桌面内容区约 1180～1240px；首页内容流与 260～280px 作者侧栏组合，平板缩减侧栏，手机转单列。
- 正文阅读区约 720～800px；正文 17～18px、行高约 1.8，目录在宽屏侧边，手机使用可收起的目录面板。
- 首屏包含站名、昵称、真实介绍、头像或原创主视觉，以及“阅读笔记”“浏览日记”入口。桌面首屏可约 420～520px，手机压缩高度，尽快露出内容。
- 全站统一标题层级、间距、圆角、按钮主次、图标和悬停状态。装饰不遮挡文字；动效支持减少动态效果偏好。
- 封面有图时展示，无图时用稳定的分类色块/图案；失效图片也有回退。避免每次刷新随机换图。
- 访客主要导航围绕首页、文章、归档、日记、资源、关于；管理入口放在次级位置。站名暂沿用当前配置，正式文案在样稿阶段确定。

桌面首页结构草图：

```text
站名 / 标识       首页 文章 归档 日记 资源 关于      搜索
────────────────────────────────────────────────────
个人首屏：介绍、头像/主视觉、两个内容入口
────────────────────────────────────────────────────
精选内容 / 置顶文章
──────────────────────────────┬─────────────────────
笔记 · 心得 · 日记 / 分类入口   │ 作者卡：介绍、社交链接
当前筛选、搜索及清空入口       │ 真实公开内容统计
图文文章列表 / 网格            │ 分类标签或近期更新
分页                          │
──────────────────────────────┴─────────────────────
站点说明 / 内容入口 / 版权与必要链接
```

手机将导航变为菜单，将筛选变为可展开区域；侧栏内容选择性移至正文后方。移动端单独设计，而不是只把桌面元素依次堆起来。

## 5. 分轮实施与交付

通常每轮先说明目标和数据流，再给出可对照的样稿/页面效果与文件清单，之后提供详细中文注释的手敲代码。用户实现后由助手review、测试、截图对比。第五轮按用户最新授权由助手直接实现并统一验收；本轮技术验收已通过，最终上线仍需用户认可整体页面效果。

交付首页、详情页、写作后台三类关键页面的桌面样稿，以及首页与详情的手机样稿。统一配色、字体、间距、图像比例和组件状态，选择可合法使用的头像与主视觉。样稿使用明确标注的示例内容。

先通过页面效果确认，再提供第一批业务代码；这一轮完成设计规格，不能仅凭换色或构建成功验收。现有数据和接口可以支撑样稿，设计不依赖先扩数据库。

实现访客布局、页头页脚、手机菜单、首页首屏、作者卡和图文列表。拆出在多个页面实际复用的 Header、Footer、ArticleCard、Pagination 等组件；沿用现有 fetch 请求方式及过期响应处理。

已于2026-10-21～22实现并统一验收，个人库备份后已执行007、原数据一致。使用与升级见[第22节](22-v2-resources-media.md)，完整范围见[验收记录](V2-RESOURCES-MEDIA-ACCEPTANCE.md)。当前为v0.11.0预发布候选，尚未提交或发布；后续描述保留为本轮目标对照。

首页和文章封面先可使用前端本地素材，后续提供受控的本地图片上传：允许类型、文件内容、尺寸和体积校验，随机文件名，限制到媒体目录，后台鉴权及 CSRF，前台使用媒体地址。明确浏览器同源访问方式；媒体数据和文章记录建立可追踪关系。

备份从“数据库与配置”扩展为“数据库、配置、媒体文件”。先完成完整恢复验证，再考虑外部对象存储。

验收：资源分组与筛选正确；错误/缺失图像不会破坏布局；图片上传失败有提示；备份恢复后封面与正文图片可正常读取。

### 第七轮：完整状态与内容打磨

统一骨架加载、零数据、筛选无结果、404、网络失败及重试。页面标题随路由/文章更新，添加基础页面描述；主题切换如纳入样稿则完整覆盖全部页面。加入必要的键盘操作、可见焦点、弹窗关闭和焦点返回。

用代表性内容检查：长篇技术笔记、短心得、公开日记、长标题、无图文章、失效图像、资源分组和空列表。站点统计基于真实公开数据，不用示例访问量充数。

验收既检查技术表现，也逐页核对统一的样稿、文本、图像、间距、内容密度和按钮状态。

### 第八轮：第二版候选验收与发布节点

执行现有测试及新增关键行为测试；用专用最小权限验收账号和独立数据库运行浏览器流程。样例初始化前核对当前 schema，所有样例 SQL 明确限定验收库，业务账号不能写个人库；准备失败时回滚。借此避免此前临时脚本隔离问题再次发生。

覆盖 320、390、768、1440px 和实际可用的真实设备/其他浏览器；无法覆盖的环境明确列为待验证。保存关键页面桌面与手机截图，逐页对照样稿，请用户确认展示效果。

同时完成旧数据升级演练、新安装、数据库与媒体备份恢复。以用户认可、功能验证和恢复能力共同决定是否适合正式发布，达到版本节点时提醒提交 GitHub 与创建 Release；发布仍由用户另行授权。

## 6. 代码与数据如何在现有基础上演进

- 保留 Vue 3、Java 17、Spring Boot、JdbcTemplate、MySQL 和当前业务数据；第二版主要工作是页面、交互和必要的数据补充。
- `App.vue` 与路由逐步承担访客/管理布局切换；`AdminView.vue` 按真实任务拆分，先迁移一个流程并通过测试，再迁移其余部分。
- 逐步建立实际复用的卡片、分页、状态提示、弹窗和 Markdown 阅读组件；不在尚未出现重复前创建通用框架。
- 文章计划补充 `cover_url`、`pinned`、`updated_at`、`deleted_at` 等字段；资源分组及媒体记录仅在对应轮次引入。具体类型、索引、接口响应及迁移编号在实现指南中确认。
- 新字段必须有旧数据兼容规则；迁移脚本追加到现有 004 之后，数据库与媒体升级前备份，禁止重跑 000～004 或重建个人库。
- 保留现有公开接口核心字段，新增字段逐步接入；后台分页等响应形状变化需同步前后端与测试。公开计数、置顶排序、草稿和回收隔离必须一起验证。
- Markdown 解析沿用现有库；代码高亮、编辑器等确有需要时再选择单一依赖，先确认导出 Markdown 兼容和学习成本。组件化不等于迁移整个大型管理模板。

第二版主线围绕展示、阅读、写作和资源。评论、聊天室、第三方登录、复杂权限、AI 生成及大屏监控先列入后续候选，不作为达到本次目标的前置条件。

## 7. 第二版上线前的共同验收标准

1. 用户确认首页、详情、后台以及手机效果达到样稿目标；测试通过之外，单独记录视觉验收结论。
2. 所有主要页面具有完整、真实的内容层次，无残留测试文案、占位按钮或英文内部枚举。
3. 笔记可长文阅读，心得可快速浏览，日记有独立组织；分类、标签、归档和搜索共同构成可返回的阅读路径。
4. 写作、发布、撤回、回收、恢复均能完成，失败不丢失当前输入；访客始终无法读取草稿或回收内容。
5. 320px 仍可操作，手机菜单、目录、代码复制与图片查看可用；宽屏的辅助区域不挤压正文。
6. 旧数据迁移及数据库、媒体恢复通过；没有未处理的认证、内容隔离和数据丢失问题。
7. 关键页控制台无未解释错误，生产构建和回归测试通过。性能测试使用约定设备及限速条件，记录首屏和图片开销后再设改进目标，不预先声称达到性能分数。

第二版的第一个具体任务是“首页、文章详情、写作后台的效果样稿与组件规范”。完成这一轮设计确认后再开始第二轮手敲实现。
